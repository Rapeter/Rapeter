# GitHub Profile README Design

## Goal

Position Kaizhong (GitHub: Rapeter) for AI Application / Agent Engineer roles. The README must let a recruiter understand the target role, credible skills, and strongest public project in a short scan.

## Audience and language

The primary audience is hiring managers and technical interviewers. The README uses concise English because GitHub is an international portfolio surface. Existing public-project names and links remain unchanged.

## Structure

1. A centered introduction: name, target role, and one-sentence value proposition.
2. A short `About` section covering agentic workflows, LLM applications, and backend systems without unsupported seniority or outcome claims.
3. A compact skills section grouped into AI/agents, backend, and engineering tools. It includes only technologies already stated in the existing README or reasonably supported by the public project description.
4. A featured-project card linking to `folio`, described accurately as a local-first AI investment research workbench with deep research, evidence-backed theses, portfolio risk analysis, watchlists, and a Pi Agent copilot. It will be labelled as an open-source project rather than claiming original authorship, because the public repository is a fork.
5. A contact section retaining the existing LinkedIn and University of Melbourne email address.
6. One GitHub statistics card and one top-languages card, using an externally hosted, privacy-preserving public image service. No visitor counter, trophies, animated typing banner, snake graph, or extensive badge wall.

## Visual style

Minimal, professional, and high-contrast: whitespace, descriptive headings, a restrained blue accent through standard shields, and no decorative animation. The page is designed for a 30-second recruiter scan.

After implementation, validate Markdown structure locally, inspect the git diff, and verify all repository, profile-card, LinkedIn, and email links use the intended values.
